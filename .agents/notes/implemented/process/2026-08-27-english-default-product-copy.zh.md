# Agent Note: 英文默认的产品与文档文案

Status: implemented

[English](2026-08-27-english-default-product-copy.md) | 中文

## 问题

HiveForge 已提供完整的英文与中文 locale 资源，但全新浏览器仍可能依据 `navigator.language` 选择中文；部分不依赖 Cordis 的基础组件还带有中文后备文案，随附 preset 元信息使用中文，文档网站根路由也发布中文。因此，即使用户没有选择中文，英文界面仍可能出现中文文本。

## 决策

英文是产品文案与文档的默认语言和规范维护语言。缺少 locale 偏好时，不论浏览器语言为何，系统都解析为英文；已显式存储的 `zh` 偏好保持有效，直到用户主动更改。英文字典定义维护中的键集合，经评审的中文字典作为可选资源保留，并保持相同键集合。

文档网站在 `/` 发布英文，在 `/zh/` 发布中文。文档配对及其伴随一致性记录仍为必需；本决策只改变维护方向，不改变[双语文档决策](2026-07-02-bilingual-docs-and-pairing-gate.zh.md)所定义的配对与保留机制。

活跃的第一方后备文案、注释、docstring、随附 preset 元信息及无后缀文档使用英文。中文 locale 字典、`.zh.md` 对侧、多语言 fixture、用户内容、必须保留的法律文本、归档 Agent Note、生成产物及第三方源码在适当情况下保留原始语言。

## 考虑过的替代方案

- **全新 profile 跟随浏览器语言。** 未采用，因为中文浏览器会在用户未明确选择时直接进入中文界面，不符合英文默认要求。
- **删除中文资源。** 未采用，因为中文仍是受支持的可选 locale，多语言测试覆盖也有意保留。
- **改写每一个汉字匹配。** 未采用，因为法律与历史文本、用户内容、测试 fixture、生成文件及第三方材料并非活跃英文产品文案。

## 结果

全新 profile 以英文打开。已有 `locale.preference: zh` 的 profile 继续使用中文，并可在 Settings → General → Language 中显式切换。英文文档位于网站根路由，中文文档移至 `/zh/`。评审需要分类剩余汉字匹配，而不能把原始字符计数当作正确性检查。

## 验证

Locale 测试覆盖没有已存偏好的中文浏览器和显式存储的中文偏好。浏览器测试为有意保留的中文 lane 写入 `zh`，并以全新中文浏览器验证英文界面。Locale 配对、定向 GUI 测试、文档投影测试、翻译配对、文档检查及仓库构建共同验证受影响路径。
